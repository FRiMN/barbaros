# Локальный поиск по коду через xerj

`xerj` — локальный поисковый движок (Elasticsearch-совместимый, узел по умолчанию
`http://localhost:9200`). Репозиторий проиндексирован под префиксом `barbaros`,
поэтому исследование кода можно начинать с поиска, а не с чтения файлов целиком.

## Когда использовать

- Ищешь, где что реализовано, перед правкой незнакомого кода.
- Нужно определение символа без обхода дерева.
- Нужны связанные файлы (второй мозг `barbaros`, инструмент `xerj_brain_ego`).

Это не источник истины: индекс локальный и может отставать от рабочей копии.

## Команды

```bash
xerj search --prefix barbaros "как устроен кэш моделей"
xerj def    --prefix barbaros ModelCacheStore
```

Через MCP доступны `xerj_search`, `xerj_def`, `xerj_semantic_search`,
`xerj_brain_overview`, `xerj_brain_ego`.

Индекс смешанный (код + проза), поэтому полезно скоупить выдачу:
`ax_format=code` — только код, поле `body` — проза, поле `text` — line-файлы
(changelog и т.п.).

## Что попадает в индекс

Индексируется только текст из git-отслеживаемых путей (`src/`, `tests/`, `docs/`,
`flatpak/`, корневые файлы). Каталоги из `.gitignore` и скрытые каталоги
(`.github`, `.idea`, `.venv`, `build`, `dist`, `repo`) не индексируются.
Бинарники и пустые `__init__.py` пропускаются.

На момент создания индекса: ~1800 записей из 67 файлов, лексические эмбеддинги
(без внешних вызовов — текст не покидает машину).

## Актуальность

Индекс не обновляется автоматически. Перед серией правок или если выдача выглядит
устаревшей, переиндексируй:

```bash
xerj autoindex "$(git rev-parse --show-toplevel)" --prefix barbaros --yes
```

Проверить состояние: `xerj autoindex status`. Номера строк из выдачи — подсказка,
а не гарантия: перед изменением файла открывай его текущую версию.

Если `xerj` в окружении нет — работай обычными `grep`/чтением файлов; на сборку,
тесты и запуск приложения он не влияет.
